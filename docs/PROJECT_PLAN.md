# Master Project Plan

**Project:** Risk-Adjusted Stock Performance Analysis and Optimal Portfolio Construction Using CAPM and MPT  
**Version:** 0.1 — research design

## 1. Objective

Develop a reproducible quantitative pipeline that evaluates selected stocks across multiple sectors, estimates systematic risk using CAPM, constructs portfolios using mean-variance optimization, and evaluates whether optimized portfolios compare favourably with transparent baselines on unseen observations.

## 2. Research questions

1. How do selected stocks differ in historical return, volatility, beta, alpha and risk-adjusted performance?
2. How do correlations and covariances influence portfolio risk?
3. How do minimum-variance and maximum-Sharpe allocations differ?
4. Does optimization add value relative to equal weighting?
5. Does cross-sector allocation reduce measured risk compared with sector-concentrated alternatives?
6. Do results persist in chronological out-of-sample evaluation?
7. How sensitive are allocations to the estimation window, return estimates and covariance estimator?

## 3. Scope

### Included in the core
- Multi-sector stock universe.
- Historical daily returns.
- Descriptive statistics and risk metrics.
- CAPM excess-return regression.
- Correlation and covariance estimation.
- Equal-weighted portfolio.
- Minimum-variance portfolio.
- Maximum-Sharpe portfolio.
- Monte Carlo weight sampling for visualization.
- Numerically optimized efficient frontier.
- Chronological holdout evaluation.
- Reproducible plots, tables and assumptions.

### Optional extensions
Choose no more than one or two after the baseline works:
- CAPM-implied versus historical expected-return inputs.
- Ledoit-Wolf covariance shrinkage.
- Rolling/walk-forward evaluation.
- Sector allocation caps.
- CVaR/downside-risk optimization.
- Transaction-cost-aware rebalancing.

### Explicitly not required initially
- Stock-price forecasting with machine learning.
- Automated trading or broker integration.
- Claims of guaranteed returns.
- A live financial-advice product.
- A complex dashboard before model validation.

## 4. Work phases and acceptance criteria

### Phase 0 — Freeze research design
Tasks:
- Audit data availability for the selected NASDAQ-listed US equity universe, benchmark and US Treasury series.
- Choose five US-market sectors and two NASDAQ-listed companies per sector as the starting design.
- Define the date window, benchmark, risk-free rate, data source and adjustment convention.
- Define the chronological holdout.

Acceptance:
- `DATA_METHODOLOGY.md` has no unresolved core convention.
- Candidate universe and source availability are recorded.

### Phase 1 — Data audit and ingestion
Tasks:
- Download/collect stock, benchmark and risk-free-rate data.
- Preserve raw data.
- Validate dates, duplicates, missingness, nonpositive prices and symbol history.
- Create a common calendar and document exclusions.

Acceptance:
- Audit report generated.
- Raw-to-processed transformations are reproducible.
- No silent forward-fill of missing prices across actual missing trading observations.

### Phase 2 — Returns and descriptive analytics
Tasks:
- Calculate simple returns.
- Compute mean, annualized return under a documented convention, volatility, skewness, drawdown and Sharpe ratio.
- Build correlation and covariance matrices.

Acceptance:
- Unit tests verify return formulas and annualization.
- Matrices are aligned and finite.
- Tables and plots are generated by a script.

### Phase 3 — CAPM
Tasks:
- Align stock, market and risk-free returns.
- Estimate excess-return regressions.
- Report alpha, beta, R-squared, standard errors/confidence intervals or other appropriate uncertainty indicators.
- Document the interpretation limits.

Acceptance:
- Regression inputs have matching dates and units.
- Known synthetic cases pass tests.
- Results are not described as proof of mispricing.

### Phase 4 — Portfolio baseline
Tasks:
- Implement equal weights.
- Implement long-only, fully invested minimum-variance optimization.
- Implement maximum-Sharpe optimization.
- Validate weight constraints and solver status.
- Report expected return, volatility, Sharpe and concentration.

Acceptance:
- Weights sum to one within tolerance.
- Long-only constraints hold.
- Optimizer results pass independent metric recalculation.

### Phase 5 — Simulation and efficient frontier
Tasks:
- Generate reproducible feasible Monte Carlo weights using a recorded seed.
- Calculate risk/return for each candidate.
- Construct the frontier using numerical optimization across target returns.
- Plot random candidates, frontier, minimum-variance point and maximum-Sharpe point.

Acceptance:
- Random sampling is clearly labelled approximate.
- Frontier points satisfy constraints.
- Numerical optimizer, not random sampling alone, determines reported optima.

### Phase 6 — Out-of-sample validation
Tasks:
- Estimate parameters on an earlier training period.
- Evaluate portfolio returns on a later test period.
- Compare optimized portfolios with equal weighting and the chosen market benchmark.
- If rebalancing is simulated, define frequency, turnover and transaction-cost assumptions.

Acceptance:
- No future observations enter parameter estimation.
- All comparisons use the same test dates and return convention.
- Limitations are stated.

### Phase 7 — Optional robustness extension
Select one enhancement, state the hypothesis, run a controlled comparison, and report whether it changes results.

Acceptance:
- The baseline remains available.
- The experiment is reproducible and does not overwrite baseline outputs.

### Phase 8 — Presentation layer
Only after the core pipeline passes tests:
- Expose stable analytical functions through an API if needed.
- Build a dashboard for stock metrics, CAPM, correlations, portfolio weights and efficient frontier.
- Keep financial calculations in the core library.

Acceptance:
- UI output matches core-library results.
- API validates requests and returns typed responses.
- UI does not calculate portfolio mathematics itself.

## 5. Required outputs

- Data audit report.
- Stock-level descriptive statistics table.
- CAPM regression results table.
- Correlation heatmap and covariance output.
- Portfolio weights table.
- Risk-return scatter and efficient frontier.
- In-sample and out-of-sample comparison table.
- Validation report documenting assumptions and limitations.
- Reproducible commands and dependency lockfile.

## 6. Definition of success

The project succeeds when the pipeline is reproducible, calculations are tested, the optimizer respects constraints, the portfolio comparison is fair, and conclusions are appropriately limited by data and model assumptions. Success is not defined as obtaining a high Sharpe ratio or beating the market in every period.
